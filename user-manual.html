Groups Setup

Conglomerate organization levels (Holding Group entities)

Hierarchy Level 0

Purpose & Objective

The **Groups Setup** functions as the root organizational tier in the system. It represents the corporate parent, conglomerate group, or holding company. This categorization allows a single HR installation to manage multiple independent subsidiaries (Companies) while supporting cross-group configurations, consolidating global compliance settings, and performing comprehensive multi-subsidiary auditing.

System & Validation Logic

Hierarchical Root: Sub-modules (Companies, Business Units) require parent-level references. Deleting a Group triggers cascading validation checks to ensure no orphaned child entities exist.

Active Scoping: Organization-scoped traits (`OrganizationScoped`) utilize the mapped company structure. If a company belongs to a parent Group, security middleware blocks unauthorized cross-group database reads.

How to Do the Task

  1. Navigate to Company Setup > Groups.
  2. Click the Create button. A side-drawer or modal form will slide open.
  3. Enter the conglomerate group name (e.g., Innovity Technologies Inc).
  4. Select status (Active) and save.

Company Types

Subsidiary legal entity classifications

Metadata Classification

Purpose & Objective

The **Company Types** module catalogs corporate legal definitions (e.g. Joint Venture, Private Limited Company, Sole Proprietorship, NGO). Defining these types assists in structural compliance reporting, taxation workflows, and applying specialized regulatory rules across subsidiary businesses.

System & Validation Logic

Classification Reference: Mapped to the `Company` creation model via foreign key. This mapping guarantees that no company can be created with an invalid or untracked business entity type.

Integrity Guard: The system prevents the deletion of a Company Type if it is currently assigned to one or more active companies.

How to Do the Task

  1. Navigate to Company Setup > Company Types.
  2. Click Create.
  3. Enter the legal status title (e.g., Private Limited).
  4. Set status to Active and click Save.

                                Company -->|Foreign Key Checks| Type

Companies Setup

Independent business subsidiaries and legal entities

Hierarchy Level 1

Purpose & Objective

The **Companies** module configures distinct commercial subsidiaries under the corporate group parent. Each company acts as an isolated entity with its own tax registry number, logo branding, payroll accounts, holiday tables, and organizational structures.

System & Validation Logic

BelongsTo Relationships: Mapped to `groups.id` and `company_types.id` as parent metadata entities.

Organization Isolation: Mapped as the primary contextual filter for security constraints. Query scoping policies prevent an HR manager at "Company A" from viewing metadata records belonging to "Company B".

How to Do the Task

  1. Navigate to Company Setup > Companies.
  2. Click Create.
  3. Fill out the entity fields: Group, Company Type, legal name, tax registry code (TIN/BIN), and address.
  4. Toggle the active status checkmark and save.

Business Units / Branches

Physical branches, office facilities, and geographic locations

Hierarchy Level 2

Purpose & Objective

The **Business Units / Branches** module represents geographical structures, physical factories, plants, corporate offices, or logistical warehouses. This maps employees to physical locations, enabling location-scoped attendance logging (via IP/geolocation) and local regulatory compliance.

System & Validation Logic

Cascading Hierarchy: Every Location is mapped to a parent `company_id`. Deleting a company triggers a cascade check blocking deletion if active branches reference it.

Attendance Binding: Allows binding regional holiday lists and shift planners specifically to a location.

How to Do the Task

  1. Navigate to Company Setup > Company Locations.
  2. Click Create.
  3. Select the parent Company.
  4. Enter the location details (e.g. Uttara Branch Office, Dhaka Factory).
  5. Define address, contact numbers, and save.

Divisions

High-level operational functional categories within the company

Hierarchy Level 3

Purpose & Objective

The **Divisions** module divides companies or business locations into broad structural clusters (e.g. Engineering, Corporate Sales, Human Resources, Operations). Operational divisions aggregate multiple localized departments and teams.

System & Validation Logic

Cascading Dropdowns: Inside employee placement forms, selecting a parent Company limits the selectable Divisions to those mapped to that company.

Organization Scoped: Automatically limits data access by adding `company_id` to query constraints.

How to Do the Task

  1. Navigate to Company Setup > Divisions.
  2. Click Create.
  3. Select parent Company and geographic Location/Branch.
  4. Enter division name (e.g. Information Technology) and save.

Departments

Functional business units and departments

Hierarchy Level 4

Purpose & Objective

The **Departments** module represents core operational departments (e.g. Software Development, Technical Support, QA, Marketing). Departments group staff under specific leadership/supervisors and establish boundaries for cost-center accounting and division-level budgeting.

System & Validation Logic

Cascading Filters: Selection is limited to the parent Division. Mapped foreign keys (`division_id`) are checked during validation requests.

Org Structure Scoping: Automatically inherits security scoping constraints from the parent company model.

How to Do the Task

  1. Navigate to Company Setup > Departments.
  2. Click Create.
  3. Select parent Company, Location, and Division.
  4. Type in department name (e.g. QA Department) and save.

Sections Setup

Granular work groups and operational teams

Hierarchy Level 5

Purpose & Objective

The **Sections** module handles the most granular organizational level (e.g. Mobile App Team, Frontend Team under Software Development Department). This structural mapping isolates workflows and enables precise employee targeting for localized notifications.

System & Validation Logic

Cascading Hierarchy: Dropdown dependencies filter selections dynamically down to Section level. Selection lists filter based on: Company > Location > Division > Department > Section.

Scoping Guard: Section records inherit context variables, ensuring secure data separation for multi-tenant setups.

How to Do the Task

  1. Navigate to Company Setup > Sections.
  2. Click Create.
  3. Select Company, Location, Division, and Department.
  4. Enter the section name (e.g. React Native Devs) and click Save.

Designations

Corporate job titles and authority weights

Hierarchy Level Weights

Purpose & Objective

The **Designations** module configures corporate job titles (e.g. Software Engineer, Senior Manager, VP). Defining designations maps employees to specific positions within the organizational hierarchy and helps coordinate approval chains.

System & Validation Logic

Designation Level Weight: An integer representing hierarchy (e.g. 1 = Associate, 5 = VP). The system enforces this hierarchy weight to validate career movements:
Promotion Rule: new_designation_level > current_designation_level
Demotion Rule: new_designation_level < current_designation_level

Workflow Routing: The system references these hierarchy weights to dynamically route career movements (like transfers or promotions) through the appropriate approval chains.

How to Do the Task

  1. Navigate to Company Setup > Designations.
  2. Click Create.
  3. Enter the designation title (e.g., Principal Tech Lead).
  4. Assign a numeric level weight (higher numbers indicate senior status).
  5. Set status to Active and save.

Pay Groups

Payroll run schedule categories and frequencies

Payroll Configuration

Purpose & Objective

The **Pay Groups** module categorizes employees based on their payroll cycle characteristics (e.g. Monthly Staff, Weekly Freelancers, Executive Pay). This grouping maps staff to distinct processing schedules, default payment frequencies, and calculation rules.

System & Validation Logic

Frequencies: Enforces frequencies (`Monthly`, `Weekly`, `Bi-Weekly`, `Semi-Monthly`).

Pay Cutoff Day: Maps the processing day (e.g., 25th of the month) to determine cutoff dates for overtime and attendance calculations.

Cascading Hierarchy: Selecting a Pay Group when defining a Pay Scale filters the available configurations.

How to Do the Task

  1. Navigate to Company Setup > Pay Groups.
  2. Click Create.
  3. Enter the title (e.g. Monthly Plant Workers).
  4. Select the processing frequency and input the cutoff day.
  5. Set status to Active and save.

Salary Grades

Standardized compensation bands and grades

Compensation Classification

Purpose & Objective

The **Salary Grades** module establishes standard compensation structures (e.g. G1, G2, Executive Grade 1). This standardization simplifies pay parity reviews, organizes employee benefits, and prevents arbitrary salary adjustments.

System & Validation Logic

Unique Grade Code: Codes (e.g., `G1`) must be unique to prevent classification conflicts.

Deconstruct Cascading Deletes: The model includes a `deleting` observer event: when a Salary Grade is deleted, all child Pay Scales associated with it are automatically deleted to maintain database integrity.

How to Do the Task

  1. Navigate to Company Setup > Salary Grades.
  2. Click Create.
  3. Input a short unique code (e.g. G9) and description name (e.g. Associate Grade 9).
  4. Set status to Active and save.

Pay Scales Setup

Minimum and maximum gross salary limits by grade and schedule

Compensation Band Rule Engine

Purpose & Objective

The **Pay Scales** module establishes standard compensation limits by mapping a combination of **Salary Grade** and **Pay Group** to a defined minimum and maximum salary range. This configuration acts as a validation check when processing promotions, demotions, salary increments, or decrements.

System & Validation Logic

Validation Threshold Rules: When a user enters adjustment values for an employee:
Let S = new_gross_salary
Rule 1: If S > max_salary, trigger UI warn event "Salary surpasses the pay scale maximum limit."
Rule 2: If S < min_salary, trigger UI warn event "Salary falls below the pay scale minimum limit."

Relationship Checks: Intersects `grade_id` and `pay_group_id` foreign keys to establish standard base parameters.

How to Do the Task

  1. Navigate to Company Setup > Pay Scales.
  2. Click Create.
  3. Select the appropriate Salary Grade and Pay Group.
  4. Enter the Minimum and Maximum salary limits.
  5. Optional: Enter a title (otherwise, a title is auto-generated in the format: Pay Group - Grade Code).
  6. Save the changes.

Movement Types

Classifications for employee career movements and adjustments

Career Adjustment Configuration

Purpose & Objective

The **Movement Types** module classifies employee career transitions (e.g. Annual Increment, Correction, Promotion, Performance Demotion, General Transfer). Defining movement types categorizes adjustments to help identify trends in organizational shifts and salary changes.

System & Validation Logic

Entity Integration: Map a Movement Type to career adjustment models using `movement_type_id`. This relation is active on: * Increment Model
* Decrement Model
* Promotion Model
* Demotion Model
* Transfer Model

Reporting Parameter: Standardized movement classifications allow the system to categorize payroll adjustments for audit logs and historical changes.

How to Do the Task

  1. Navigate to Company Setup > Movement Types.
  2. Click Create.
  3. Enter the classification name (e.g. Annual Performance Increment).
  4. Provide an optional description detailing when to use it.
  5. Set status to Active and save.
