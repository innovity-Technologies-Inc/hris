Innovity Approval Engine

A comprehensive implementation tutorial and interactive dashboard detailing architecture, schemas, listeners, and timeline flows.

Decoupled Workflow Execution

The package handles state management, timeline routing, and decision validation. The host application handles structural security, notifications, and final database adjustments via clean event routing mappings.

Phase 1: Workflow Ignition

Initiating Approval

The workflow starts when the host application model requests an approval process by executing: $model->startWorkflow(string $module)

Trait Class & Helper Path:

vendor/innovity/laravel-approval-engine/src/Traits/Approvable.php

Blueprint Lookup:

Instantiates WorkflowGenerator::generate($approvable, string $module) which queries active records in the approval_workflows table where module = $module, evaluates requester Inclusion & Exclusion criteria (auto-approving/bypassing if excluded or if the creator is not within the target inclusions), and resolves the matching workflow.

Database Insertion:

Generates a master record in the approval_requests table with status 'pending' and serialized request data payloads.

Phase 2: Task Emission

Distributing Tasks

Decides which approval step requests are written to the database using the engine's Task Emitter: TaskEmitter::emit(ApprovalRequest $request)

Emitter File Path:

vendor/innovity/laravel-approval-engine/src/Services/TaskEmitter.php

Sequential Step Mapping:

Invokes emitSequential(), finding the next uncompleted order step (e.g. step 1, then step 2) and inserting a single pending task.

Random Step Mapping:

Invokes emitRandom(), creating active task request entries in the database for all steps simultaneously.

Phase 3: Resolver & Alerts

Notification Routing

Listens for step insertions and resolves which users are authorized to approve the current step:

Dynamic Database Hook:

Listens via ApprovalStepRequest::created(closure) defined inside AppServiceProvider@boot.

Approver Resolution Interface:

Resolves User IDs via ApproverResolverInterface::resolve($stepId, $approvable) which operates without global scopes.

Notification Builders:

Checks if a dynamic route named "$module.show" exists to construct direct redirect links, then builds in-app alerts and dispatches emails.

Phase 4: Action Resolution

Decision Processing

Validates reviews, executes locks, updates statuses, and fires completion triggers:

Secure Controller Path:

vendor/innovity/laravel-approval-engine/src/Http/Controllers/ApprovalActionController.php

Concurrent Isolation:

Runs query locks (lockForUpdate()) inside a transaction (DB::transaction) to prevent race conditions during double-submissions.

Decision Delegation:

Updates step logs and determines workflow outcomes in ApprovalResolver::resolve($stepRequest, $status, $comments), broadcasting completion events.

Step 1 Install & Publish Assets

Install the package via Composer, publish config/migration files, and run database migrations:

composer require innovity/laravel-approval-engine
php artisan vendor:publish --tag=approval-engine-config
php artisan vendor:publish --tag=approval-engine-migrations
php artisan migrate

Step 2 Implement the Approvable Trait

Attach the Approvable trait to any Eloquent model that requires approval workflows:

use Innovity\ApprovalEngine\Traits\Approvable;

class Leave extends Model {
    use Approvable;
}

Step 3 Implement Approver Resolver

Create the ApproverResolver service and bind the ApproverResolverInterface inside AppServiceProvider@register:

namespace App\Services;

use Innovity\ApprovalEngine\Contracts\ApproverResolverInterface;

class ApproverResolver implements ApproverResolverInterface {
    public function resolve(string $stepId, $approvable): array {
        // Query database and return array of authorized approver user IDs...
    }
}
// In AppServiceProvider@register
$this->app->bind(
    ApproverResolverInterface::class,
    ApproverResolver::class
);

Step 4 Decouple Event Listeners (Service Provider)

Define the registry map and listen dynamically in AppServiceProvider@boot:

private array $workflowListeners = [
    'leave' => \App\Listeners\Workflow\LeaveWorkflowListener::class,
    'promotion' => \App\Listeners\Workflow\PromotionWorkflowListener::class,
    'office-information' => \App\Listeners\Workflow\ProfileUpdateWorkflowListener::class,
];
// In AppServiceProvider@boot
Event::listen(ApprovalCompleted::class, function (ApprovalCompleted $event) {
    $module = $event->approvalRequest->workflow->module;
    if (isset($this->workflowListeners[$module])) {
        $listener = app($this->workflowListeners[$module]);
        $listener->handleCompleted($event);
    }
});

Approval Action Lifecycle

Once a workflow has been initiated, it enters a lifecycle where an authorized reviewer acts on the request. Here is the step-by-step process:

1. Workflow Initiation

A request is submitted (e.g. $leave->startWorkflow('leave')), generating the master record and the first pending task request in the database.

2. Notification Sent

The system catches the database event, resolves the reviewer using ApproverResolver, and fires in-app bell alerts and emails pointing to the request URL.

3. Reviewer Action

The reviewer loads the request view page. The workflow_history Blade component displays the Approve/Reject buttons, allowing them to type comments and submit.

4. Controller & Resolver Execution

The submission sends an Axios AJAX POST request to ApprovalActionController@action, which locks the row (lockForUpdate) inside a transaction, processes the decision, and updates the step request status.

ApprovalRequested

Dispatched during request initialization inside the package generator class.

File Path: vendor/innovity/laravel-approval-engine/src/Services/WorkflowGenerator.php

Trigger: Fired when an approvable model initiates a new workflow via $approvable->startWorkflow().

ApprovalStepApproved

Dispatched when a single step is approved.

File Path: vendor/innovity/laravel-approval-engine/src/Services/ApprovalResolver.php

Trigger: Fired when an individual step request is approved by an assigned reviewer.

ApprovalCompleted

Dispatched when the overall workflow satisfies all required approvals.

File Path: vendor/innovity/laravel-approval-engine/src/Services/ApprovalResolver.php

Trigger: Fired when all blueprint step requirements are satisfied, completing the entire workflow successfully.

ApprovalRejected

Dispatched when the overall workflow is rejected.

File Path: vendor/innovity/laravel-approval-engine/src/Services/ApprovalResolver.php

Trigger: Fired when a step rejection fails the sequential flow or mathematically prevents the random flow from succeeding.
