Innovity Approval Engine

An interactive breakdown of the HRMS Approval Workflow Engine architecture, core methods, and database schemas.

Step 1

Initiation

The workflow starts via the startWorkflow() method provided by the Approvable trait.

  • Looks up active blueprint for module.
  • Creates ApprovalRequest (Master Tracker).
  • Dispatches ApprovalRequested event.
Step 2

Task Emission

The TaskEmitter determines how to generate actionable tasks (ApprovalStepRequests).

Sequential: Emits one step at a time based on order.

Random: Emits all required steps simultaneously.

Step 3

Routing & Notifications

The ApproverResolver determines exactly who holds the required authority level for the given employee.

  • Generates standard email notifications.
  • Generates in-app dashboard bell alerts.
  • Dynamically builds redirect URLs (e.g., {module}.show).
Step 4

Processing & Finalization

The ApprovalResolver processes Approve/Reject actions via AJAX.

Once logic concludes, it emits ApprovalCompleted or ApprovalRejected. Finally, the WorkflowStatusListener updates the core HRMS model status in the main app.

The Approvable Trait

Attached to subject models (e.g., Leave, Salary). It provides the core relationship methods and the ignition switch to begin workflows.

// In a Controller (e.g., SalaryController@store)
$salary->startWorkflow('salary');

*Note: Workflows do NOT trigger automatically on model save. You must manually call this method to prevent Drafts from emitting tasks.

ApproverResolver

Implements ApproverResolverInterface to bridge the package with HRMS business logic.

  • Uses withoutGlobalScopes() to securely resolve users regardless of acting contexts.
  • Matches target UserType against the employee's current departmental structural IDs.

WorkflowStatusListener

The final puzzle piece. Listens to ApprovalCompleted and ApprovalRejected.

It takes the completed payload from the package and physically mutates the main HRMS model (like setting status = 'approved' on the Leave record) ensuring strict separation of concerns.
