Dynamic Employee Field Engine

A robust enterprise design separating the form into four layers: Sections > Fields > Options > Data.

employee_sections

Defines Major Profile Blocks

This table handles the major groupings. The most important column is storage_type, which tells the system if this section holds one object (single) or multiple objects (repeater).

Column Type Example
id PK 1
name String Education
storage_type Enum multiple (or single)
display_order Integer 2

employee_fields

The Core Schema

This table is the heart of the engine. It dictates the label, grid width, input type, data source, and complex validations via JSON.

Basic Configurations

  • label: Degree Title

  • column_width: 6 // Renders as col-md-6
  • component: input

Dynamic Approval Workflow Engine

A multi-level, polymorphic routing engine utilizing the OrganizationScoped trait.

1. Workflows

Registers modules that require approval (e.g., Leave, Promotion, Expense).

2. Workflow Steps

Maps sequences to User Types.
Ex: Step 1 -> `Department`, Step 2 -> `Group`.

3. Requests & Logs

Polymorphic link storing the `employee_id` and `current_step_order` to track the state.

The OrganizationScoped Superpower

Employee
Submits Leave Request
Morphs to ApprovalRequest
Approval Engine
Checks Workflow Steps • Sets current_step = 1 (Department)
Department Head Logs In
Queries: ApprovalRequest::where('current_step', 1)
OrganizationScoped Trait Magic:

The trait intercepts the query. Because the `approval_requests` table stores the `employee_id`, the trait automatically restricts the results so the Department Head ONLY sees requests belonging to employees inside their specific department.
